TYPE = PASSWORD (Mot de passe ou code PIN) : le secret d'authentification lui-meme, la chaine ou le code confidentiel qu'une personne presente pour ouvrir une session ou deverrouiller un acces.
FORMAT : il n'en existe aucun. Toute suite de caracteres peut etre une valeur de ce type : quatre chiffres, un mot du dictionnaire, une phrase entiere avec des espaces, une chaine aleatoire de trente caracteres. Le motif (a) VIOLATION DE FORMAT est donc INTERDIT ici, sans exception : ni la longueur, ni l'alphabet, ni l'absence de caractere special, ni la faiblesse apparente ne justifient un rejet, et le libelle couvre aussi le code confidentiel purement numerique.
TYPES CONCURRENTS A NOMMER :
- une cle d'API ou une cle d'acces : elle authentifie un programme aupres d'un service la ou ce type authentifie une personne, et le contexte qui la nomme ainsi emporte le rejet ;
- un jeton d'acces, un jeton porteur, un jeton de session ou de rafraichissement, annonce comme tel par le contexte ou par le nom du champ, la seule forme a trois segments separes par des points ne suffisant pas ;
- un identifiant de connexion ou un nom d'utilisateur, qui designe le compte et non le secret qui l'ouvre ;
- une adresse e-mail, y compris quand elle sert d'identifiant de connexion et qu'elle figure juste a cote du secret ;
- une empreinte, un condensat ou un hash annonce comme tel, meme quand il derive bien d'un secret ;
- une politique ou une exigence (longueur minimale, complexite, duree de rotation), qui enonce une regle et non une valeur ;
- la locution qui nomme le type, en francais comme en anglais, y compris les formes du code PIN et du code confidentiel que le libelle couvre, citee sans son contenu, seule ou suivie de deux points comme libelle de champ : c'est le motif (c), meme si la vraie valeur suit juste apres dans le contexte ; en revanche, si le span delimite par >>> <<< est la valeur elle-meme, un secret egal au nom du type reste TRUE_POSITIVE ;
- un nom de champ, de parametre, de colonne ou de variable d'environnement cite sans son contenu, une reference de variable non resolue, un gabarit entre crochets ou accolades, une valeur deja masquee par des etoiles ou des X.
Dans tous ces cas, le motif (b) exige que le contexte proche NOMME le type concurrent ; sans cette mention, la reponse est UNSURE, jamais FALSE_POSITIVE.
CE QUI RESTE TRUE_POSITIVE : un secret faible, trivial, par defaut, publie dans une documentation, partage ou reutilise ; celui d'un compte technique, de service ou d'un environnement de test, le motif (d) ne s'appliquant jamais a un secret ; une valeur nue, sans guillemets et sans aucun mot-cle autour, posee dans une chaine de connexion, une ligne de commande, un fichier de configuration ou un formulaire, l'absence d'indice contextuel n'etant jamais un motif de rejet ; un code purement numerique annonce comme confidentiel ; une chaine qui ressemble a une cle ou a un jeton des lors que le contexte l'annonce comme le secret d'un compte.
