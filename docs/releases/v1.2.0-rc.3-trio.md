# AI Sentinel v1.2.0-rc.3-trio

Cette RC réunit le détecteur Trio (Bards, CBX et Ettin), les fournisseurs du juge
LM Studio/oMLX/Strata, les catégories évaluées par le juge et la nouvelle
présentation des LLM locaux externes. Le juge reste un post-filtrage à la demande.

Le catalogue expérimental des 118 regex nationales SSN/Tax ID est supprimé.
Au démarrage de l’API, ses anciennes entrées de configuration sont retirées des
bases existantes. Les résultats et décisions des scans sont conservés. Les règles
AVS et SOCIALNUM historiques, les clés d’API et les validations Presidio restent.

Les variantes expérimentales du nouveau juge, leurs changements de contexte et
la vue par occurrence dépendante ne sont pas inclus dans cette RC. Aucun nouveau
seuil issu des expériences en cours n’est appliqué.

## Installer ou mettre à jour

Depuis la copie du dépôt correspondant au tag `v1.2.0-rc.3-trio`, les trois images
utilisent le même tag dans les fichiers Compose standard et DGNSI.

```bash
docker compose pull pii-detector pii-reporting-api pii-reporting-ui
```

Pour une première installation, démarrer aussi la base et la gestion des secrets :

```bash
docker compose up -d
```

Puis recréer les trois services applicatifs, sur une installation neuve ou existante :

```bash
docker compose up -d --force-recreate pii-detector pii-reporting-api pii-reporting-ui
```

Ouvrir l’interface sur `http://localhost:4200`. Pour scanner avec Trio, activer
Trio et les modèles souhaités dans les réglages ; Trio est désactivé par défaut.
Pour un scan sans LLM externe, désactiver aussi Ministral-PII. Renseigner ensuite
la connexion Confluence dans l’interface.

Les poids Trio sont téléchargés au premier chargement et conservés dans le volume
`huggingface-cache`. Une connexion Internet est nécessaire si le cache est vide.
Sous Docker sur Mac, Trio utilise le CPU. Le premier appel charge les modèles.
Pour un juge LLM hébergé sur la machine hôte, utiliser `host.docker.internal`
comme hôte depuis les conteneurs, avec le port du serveur choisi.

## Validation locale

- 1 256 tests unitaires Python, 1 890 tests Java et 757 tests UI réussis.
- Build UI de production et construction des trois images Linux ARM64 réussis.
- Démarrage API/UI sur PostgreSQL 18 jetable et chargement des 104 types Trio.
- Trois réglages Regex conservés ; aucune entrée du catalogue national restant.
- Chargement réel des trois modèles dans l’image Linux et appel gRPC synthétique
  avec configuration PostgreSQL : aucune erreur des détecteurs.
- Parcours UI avec API réelle : choix Trio et persistance d’un interrupteur modèle.

Le test utilise des données synthétiques et un cache de modèles existant en lecture
seule. Aucun scan Confluence ni caviardage n’a été lancé pour cette validation.
Les tests locaux portent sur ARM64 ; les images AMD64 sont construites par la CI.
